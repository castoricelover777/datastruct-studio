============================================================
一、为什么做
============================================================

学数据结构时的个人痛点：代码能看懂但是就写不出来。

不是不懂逻辑，是手不熟。看链表插入觉得"就这么回事"，白纸上写不出
s->next = p->next; p->next = s; 。

试过的办法都不太管用：
· 看视频：看时懂，看完忘
· 抄代码：抄完还是不会默写

所以我想做一个工具解决它。

============================================================
二、产品是什么
============================================================

一句话：帮"能看懂但写不出"的人，通过"拆模块 + 去注释 + 默写 +
编译验证"真正掌握数据结构代码的桌面工具。

所以它不是视频课、IDE、题库
而是：一整个陈越数据结构课程蒸馏后的一个小知识库和工具库

现在三个形态都能用：
· 桌面便携版（一个 exe，双击就开，不用装）
· 在线版（不用下载，打开链接就能看）
· 每段动画单独的 SVG 文件（能直接贴在 README 里自动播放）

我一开始的想法只是自己用。做到后面发现，别人也可能需要，所以做成了
能直接给别人用的样子。

============================================================
三、给谁用
============================================================

和我一样正在学数据结构的大学生：
· 能看懂代码，独立写会卡壳
· 考前突击，需要快速过一遍
· 希望有一个工具库可以供自己随时查各类算法八股文

四、核心功能
============================================================

4.1 模块化阅读

把完整代码切成独立模块，以单链表为例，我把它切成 12 块：
01 结构定义
02 creatNode
03 InitList
04 applist
05 GetElem_L
06 LocateElem
07 ListInsert  
08 ListDelete  
09 printList
10 freeList
11 main
12 完整源码

每个模块顶部显示：模块名、一句话作用、难度星级、依赖模块、前置视频。

为什么这样切：300 行一起看会懵
但是一次只看 15 行的 ListInsert可以帮我聚焦注意力和背诵默写

4.2 三档注释

分别为详细注释]，精简注释，和无注释
·详细：逐行解释 + ASCII 指针图
·精简：只标关键步骤
·无注释：只有纯代码

切到"无注释"时，函数签名、变量名、缩进完全不变，只剥注释。
这一点是硬要求：如果连代码本身都变了，那就不能拿来练默写了。

例如 ListInsert 详细注释里的图：

插入前：
p            p->next
↓              ↓
[a_{i-1}]  →  [a_i]  → ...

插入后：
p         s        p->next
↓         ↓          ↓
[a_{i-1}] → [新] →  [a_i] → ...

① s->next = p->next;   先连后
② p->next = s;         再连前
顺序反了就丢了 a_i

4.3 空白编辑器 + 编译

点"编辑模式"切换：
· 初始完全空白，不给你抄
· 语法高亮、行号、括号匹配
· Ctrl+Enter 编译运行
· 失败红色显示错误，点击错误行跳转
· 右侧可折叠参考答案，写完对比

编译器：优先用系统 gcc，没装就用内置 TCC（约 500KB）。
开箱即用，不配环境。

为什么重要：默写最怕"以为写对了"，编译一下错在哪一目了然。

4.4 动画系统

每个模块配动画：链表指针转向、栈的入出、队列进出、AVL 旋转、
DFS/BFS 点亮、排序柱子交换、哈希探测。

到 v2.1.3 实际做了 188 段，覆盖全部已完成模块（186 个），没有遗漏。

播放器：

▶ ⏸ ⏮ ⏭   00:12 / 00:45
●━━━━━━━━━━━━━━━━━━━━━━
──────●─────────────────
[0.5x][1.0x][1.5x][2.0x]  [循环][单步]

这几条是我提的功能要求：

· 进度条可拖动，拖到哪画面跳到哪，实时刷新
· 单步模式：一次前进一个关键帧（如"指针 A 改指向"算一步）
· 关键帧标记：进度条小圆点，悬停显示步骤名
· 快捷键：空格播放/暂停，左右方向键前后 5 秒

为什么进度条要能拖：
其实我感觉只能从头播的动画等于没有，我的思考速度要由我决定而不是动画

动画与代码联动：动画播到"分配新节点"，右边代码
LinkList s = creatNode(e); 高亮；点代码某行，动画跳到对应帧。

动画用 SVG 自带的动画做的，不靠 JavaScript 跑。这样有三点好处：
一是能直接贴在文档里自动播放；二是不依赖浏览器脚本；三是能精确跳到
某一时刻去截图检查（后面第九节要用到）。

七、技术

（整个项目的代码都是 AI 生成的。我对下面这些技术的了解程度分三档：
"会一点" = 能看懂、能改；"跟着做过" = 跑过命令、知道它在干嘛；

【让网页变成桌面程序】

· Electron —— 跟着做过
  把网页打包成一个 exe，双击就开，看起来跟普通软件一样。
  项目入口在 electron/main.js。

· 打包工具 Electron-Builder —— 跟着做过
  打成便携版，96.2 MB，不用安装，拷到哪都能跑。

【让我能敲代码的那个框】

· 编辑器 —— 跟着做过
  项目里没有用 Monaco 这一类现成的编辑器库，代码是 AI 写的。
  它的做法是：把一个透明的输入框叠在语法高亮文字上面，两层对齐。
  好处是撤销、选中、输入法这些全是浏览器自己负责的，不用另外写；
  代价是两层的字号和行距必须完全一致，不然光标会跑偏。
  （这条是我读代码时看到的，做法不是我提的。）

· 编译用的 TCC —— 跟着做过
  项目自带一个 152 KB 的迷你 C 编译器。优先用系统里的 gcc，没有就
  用自带的。这样别人不用配环境就能验证自己默写对不对。

【让我看见过程的部分】

· SVG 动画（188 段）—— 跟着做过
  用的是 SVG 自带的动画标签，不是 JavaScript。这样能直接贴在文档里
  自动播放，也能精确跳到某一时刻截图去检查。

【内容和程序怎么分开】

· JSON 数据（58 个文件）—— 会一点
  模块信息、三档注释、动画数据都放在这里。内容和程序分开以后，
  加新内容不用动程序。

· Node.js 脚本（16 个）—— 会一点
  改一次 C 代码，跑一条命令，数据、动画、网页就全部重新生成。
  另外还有一条检查命令，10738 条，跑一遍就知道有没有改坏。

【还没有的】

· 前端框架（Vue / React 等）—— 还不会
  界面是手写 HTML/CSS/JS。页面不多，手写更直接，文件也更小。

· 后端 / 服务器 —— 还不会
  现在是纯本地程序加静态网页，不需要服务器算东西。以后要给检索的
  小工具接大模型接口的时候才会碰到。

【实际大小】便携版 96.2 MB（原来定的上限是 250 MB）

【几条约束】
· 不联网也能用
· 动画和代码分开存放
· 结构数据化，不写死在程序里

============================================================
九、"一份真源"：改一次代码不用改三个地方
============================================================

这一节是 v2.1 加的，因为踩了坑。

原来的问题：

v2.0 的时候，网页、动画、文档是分开的。我改一次 C 代码，要分别去改
这三处。改漏过好几次——网页更新了动画还是旧的，或者动画改了文档没跟上。
每次都要来回找，很烦。

后来改成了现在这样：

让它们都从同一份文件生成。我只维护 C 代码那一份，其他全部自动跑出来。

（顺带说清楚边界：我只负责提要求和验收。这个"从一份文件生成"的办法，
以及具体怎么实现，都不是我提的。）

现在的走法：

  C 代码（我只维护这一份）
     ↓ 一条命令
  数据文件（模块、三档注释、元数据）
     ↓ 一条命令
  188 段动画
     ↓ 一条命令
  在线版网站 + 便携 exe

  旁边还有一条：检查命令，10738 条，随时跑

好处很直接：改一次 C 代码，跑一遍命令，网页动画文档全跟着变，
再也不会漏。坏处也有一点：多学了几条命令，不过比来回改三个地方划算。

现在整个流程是 16 个脚本、大概 2800 行，全部是 AI 写的。
我要的只是"改一处、其他地方自动跟上"这个效果，具体怎么实现不是我管的。

============================================================
十二、顺手做的一个检索小工具
============================================================

v2.1 顺手加的一个东西，单独说一下，因为它和我的兴趣方向有关。

项目里那 186 个模块，其实是天然分好块的材料。我一直对 AI 那边感兴趣，
就想到：能不能让它自己去这些模块里找答案？

做法很简单，分两步（代码一样是 AI 写的，我只是把这两步想清楚了）：
第一步，在这 186 个模块里搜出和我问题最相关的 3 个。
第二步，把这 3 个模块的内容连同问题一起发给 DeepSeek，让它只根据这些
内容回答，并且注明是从哪个模块来的。

第一步的搜法用的是"倒排索引"，就是在数据结构课上学过的那种：
先建一张"词 → 哪些模块里有这个词"的表，查的时候直接跳过去，
不用一个个翻。这是整个项目里我唯一能讲清楚原理的地方。

顺手记一个踩过的坑：一开始是按单个汉字切的，查"指针"的时候，
返回的第一个是"头文件与 typedef"——因为"指"和"针"这两个字在很多模块里
都出现过，单个字区分不出来。后来改成按相邻两个字切，"指针""遍历"
"队列"这样才有意义。

这个工具现在还不算好用，检索有时候会找不到。不过检索和生成是分开的，
所以哪一半不准，能看得出来。
