一、为什么做
学数据结构的时候我有个毛病：代码看得懂，但是写不出来。
不是不懂逻辑，是手不熟。看链表插入觉得"就这么回事"，白纸上写不出
s->next = p->next; p->next = s; 。
看视频：看的时候懂，看完就忘。抄代码：抄完还是不会默写。
所以我想做个东西逼自己写。

二、这东西是什么
一句话：帮"能看懂但写不出"的人，通过拆模块、去注释、默写、编译验证，
把数据结构的代码真正写会。它不是视频课、IDE 或题库，是把陈越那门课拆开做的练习工具。
三种用法：桌面便携版（双击就开，不用装）、在线版（打开链接就能看）、每段动画单独的图片。
一开始只想自己用，做到后面觉得别人可能也需要，就做成了能直接给别人用的样子。

三、给谁用
和我一样正在学数据结构的大学生：能看懂代码但独立写会卡壳；考前要快速过一遍；
想有个地方随时查各类算法怎么写。

四、功能

4.1 拆成模块看
把完整代码切成一块一块。单链表切成 12 块：结构定义、creatNode、InitList、
applist、GetElem_L、LocateElem、ListInsert、ListDelete、printList、freeList、
main、完整源码。
每块上面显示：名字、一句话作用、难度星级、依赖哪一块。
为什么这样切：300 行一起看会懵，
但一次只看 15 行的 ListInsert，我就能看进去，也背得下来。

4.2 三种注释
详细注释（逐行解释，配指针图）、精简注释（只标关键步骤）、无注释（只有代码）。
切到"无注释"的时候，函数名、变量名、缩进完全不变，只把注释去掉。
这条是硬要求：如果代码本身也变了，就不能拿来练默写了。
比如 ListInsert 里的图：
插入前：
p            p->next
↓              ↓
[a_{i-1}]  →  [a_i]  → ...
插入后：
p         s        p->next
↓         ↓          ↓
[a_{i-1}] → [新] →  [a_i] → ...
① s->next = p->next;   先连后
② p->next = s;         再连前
顺序反了就丢了 a_i

4.3 空白编辑器 + 编译
点"编辑模式"就能默写：一开始完全空白，不给你抄；有语法高亮和行号；写完 Ctrl+Enter
编译，错了标红并点得到错误行；右边可以展开参考答案对照。
编译器优先用系统 gcc，没装就用项目自带的，不用配环境。
默写最怕"以为写对了"，编译一下错在哪一目了然。

4.4 动画
每块配动画：链表指针转向、栈的入出、队列进出、AVL 旋转、DFS/BFS 点亮、排序柱子交换、
哈希探测。到 v2.1.3 做了 188 段，覆盖全部已完成的模块，没有遗漏。
我提的要求是：进度条能拖、能变速、能单步、能循环。
为什么一定要能拖：其实我感觉只能从头播的动画等于没有，我的思考速度要由我决定而不是动画。
动画和代码要联动：动画播到"分配新节点"，右边对应那行代码跟着高亮；点代码某行，
动画跳到对应那一帧。

4.5 另一种语言版本

工具栏上除了"详细 / 精简 / 无注释"，旁边还有一组 C / Python。
同一个模块，可以切着看两种语言怎么写同一件事。

这不是把 C 翻译一遍就完事。数据结构这门课教的是 C，
但我自己想看看同一套算法换个语言长什么样 —— 尤其是三件事：

- C 要 malloc、free、传二级指针改指针本身，Python 里对象就是引用，
  没有这两样东西，代码短一截
- C 的 for (j = length; j >= i; j--) 到 Python 变成 range(length, i-1, -1)，
  那个不包含右端点和第三个参数 -1，是初学最容易漏的地方
- 同一段逻辑换个语言容易写出"语法对、意思错"的版本。比如 KMP 求 next 表
  用的是 while 而不是 for，因为失配时要把长度退回到次长的前后缀接着试，
  这个"退"不是简单的循环变量减一；C 和 Python 都能写对，但抄错一步
  就变成死循环或者错的后缀表，而且编译/解释都不报错

切语言的时候，注释档位、行号、语法高亮都跟着切。
还没写 Python 的模块，按钮是灰的，鼠标放上去会说明原因，
不会点下去什么都不发生。

做法上，Python 版跟 C 版一样是"标注文件"：同一个标记、同一套解析器，
只是注释前缀从 // 换成 #。所以两种语言的模块编号、三档注释是对齐的，
可以逐块对照。

这里要说清楚：C 和 Python 的代码一行都不是我写的，都是 AI 生成的。
我做的是定框架、提功能要求、以及实际拿来用、发现问题。
这次加 Python 版也是我提的要求。做的过程中翻出一个 C 版的老 bug，
不过老实说不是我肉眼发现的，是"把两种语言的输出逐字节比一遍"这个
检查抓出来的 —— 具体见第十节第 5 条。

六、界面
左边一条章节目录，右边分三块：上面读代码（三种注释切换），中间默写并编译，
下面放动画。底部一条状态栏显示编译器和当前模块。
视觉：清爽、简约。有深色模式，工具栏最右边有个按钮能切，点一下整个界面变深，
下次打开还是你选的那个。

七、技术（我知道多少说多少）
代码都是 AI 写的，我没动手写。下面说的是"我为什么要这些"。
套一层 Electron
  我想一套东西同时有桌面版和网页版，不想写两遍。
内容和程序分开
  模块、注释、动画数据都放单独的文件里，不放程序里。以后加新内容不用动程序。
数据从代码生成
  一开始不是这样，改一个地方要改好几处，老漏。现在都从 C 代码自动生成（下一节细说）。
要能自己检查
  东西一多，改坏了不容易发现。所以配了一套自动检查，跑一遍就知道。
还没碰过的：前端框架和后端都不会。界面是手写的 HTML/CSS/JS，页面不多够用；
没有后端，本地程序加静态网页，用不着服务器。

八、改一次东西要跑几个地方
这一节是我最想说的，因为它不是某个功能，是整个东西的骨架。
原来的问题：v2.0 的时候，网页、动画、文档是三份。我改一次 C 代码，
要分别去改这三处，改漏过好几次，每次都要来回找，很烦。
现在的做法：只留一份 C 代码，其他全都从它生成，一层一层往下走：
  C 代码（唯一要维护的东西）
     ↓ 跑一条命令
  数据文件（模块、三种注释、动画数据）
     ↓ 跑一条命令
  188 段动画
     ↓ 跑一条命令
  在线版网站 + 便携 exe
  旁边还有一条：检查，随时能跑，改坏了立刻知道
好处：我只管一份东西，改完跑一下，后面全部跟着变。
这个办法是它想出来的，我提的是效果：改一处，别的地方得自己跟上。

九、验收
用起来的部分：目录能折叠能搜、链表三个页签能切、三种注释切过去代码结构不变、
每块都有动画、进度条能拖能变速能单步、代码和动画高亮对得上、编译正常、两端都能开。
我自己最在意的四条：
· 动画任意时刻都得有内容，不能出现空白
· 三种注释必须一模一样（只差注释），不能只"看起来一样"
· 动画循环播放时首尾要接得上，不能跳
· 本地、桌面、下载页三处的文件要一致
这十几项一起跑就是那 10738 条检查，结果必须是 0 个失败。

   每个部分要到什么程度、然后自己拿它学，哪里卡手就提出来改。
2. 深色模式的按钮以前被做漏过。v1.0 的时候界面上有，做 v2.0 那次重构把
   按钮删掉了，配色的样式还留着，结果只能改设置文件才能开。这次我自己
   翻代码发现了，把按钮加回来了，也验证过能来回切。
   记在这里是因为：东西一多，这种"改一半漏一半"的事最容易发生。
3. 图、排序、散列这三块我自己还没学到，内容是先做出来了，
   所以这几章的东西我现在还说不出个所以然。
4. 前面几章我也没有每一行都看透。有两三个模块我能讲清楚，但不是全部。
5. 做 Python 版的时候，发现 C 版有一处代码是错的。中缀转后缀那个弹栈，
   写成了"先把栈顶下标减一、再取"，等于每次弹栈都读错一格，最后一个
   运算符直接丢了。注释里明明白白写着"3+4*2 应该得到 342*+"，实际跑出来
   是"342+"，还打了"表达式有误"。
   为什么一直没发现：因为界面上那个"预期输出"是拿同一份错代码跑出来的，
   两边一致，看不出问题。
   这次是因为要把两种语言的输出逐字节比一遍才暴露出来。
   这件事让我意识到：**验收不能只看"跑起来了"**，得有个独立的参照物。
   我一直是这个项目的验收人，但这次是工具替我发现的，不是我肉眼发现的。

十二、另外两件事
一个检索小工具
项目里那 214 个模块本来就是分好块的材料。我一直对 AI 感兴趣，就想到能不能
让它自己去这些模块里找答案。做法两步（代码是 AI 写的）：先搜出最相关的 3 个
模块，再把这 3 个连同问题发给 DeepSeek，让它只根据这些内容回答并注明来源。

检索分两层。第一层是"倒排索引"，先建一张"词 → 哪些模块里有这个词"的表，
查的时候直接跳过去，负责快速圈出候选。

第二层用 **KMP**，这是字符串那一章讲的东西，也是这个工具里我唯一能说清
原理的地方：模式匹配最直白的写法是一个字符一个字符比，失配了就把主串往回
退重来，最坏要 O(n×m)；KMP 先在模式串上算一张 next 表，记下"前几位里最长
的那个既是前缀又是后缀的长度"，失配时靠这张表决定下一步从哪儿接着比，
主串指针一直往前不回退，复杂度降到 O(n+m)，而且能数出出现了几次（含重叠）。

放在检索里的用处是：倒排索引只回答"这个词在不在这个模块里"，不管出现几次。
圈出候选之后，再用 KMP 在标题类文本里数一遍每个词真实出现多少次，
把"只是提了一嘴"和"整段都在讲它"区分开。

这里我踩过两个坑，都挺典型：

  一个是切词。一开始按单个汉字切，查"指针"返回的第一个是"头文件与 typedef"
  ——因为"指"和"针"在很多模块里都出现过。后来改成按相邻两个字切成词组。

  另一个是权重没分词的"具体程度"：反排索引把查询切成"快/快速/速/速排/
  排序/序"这些碎片，短碎片到处都是，结果查"快速排序"返回的是希尔排序。
  给 KMP 那一层按词长加权（"快速排序"比"排序"值钱得多），并且把节标题、
  章标题也纳入比对之后才对——现在查"快速排序"命中的就是那一节。

还有一个不算坑但值得记的：这个工具一开始只装了 186 个模块，链表那一节
26 个模块整个是空的。原因是模块清单是从 tree.json 读的，而大模块在
tree.json 里只存了"有几个模块"这个数字，真正的清单在 chapters 里。
它不报错，表现就是"查链表什么都搜不到"——东西少了但看着一切正常，
这种最难发现。

这个工具现在比之前好用多了，但还不算灵。不过检索和生成是分开的，
哪一半不准能看得出来。
