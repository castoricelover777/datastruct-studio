============================================================
一、为什么做
============================================================

学数据结构时的个人痛点：代码能看懂，但是写不出来。

不是不懂逻辑，是手不熟。看链表插入觉得"就这么回事"，白纸上写不出
s->next = p->next; p->next = s; 。

看视频：看时懂，看完忘。抄代码：抄完还是不会默写。所以想做一个工具解决它。

============================================================
二、产品是什么
============================================================

一句话：帮"能看懂但写不出"的人，通过"拆模块 + 去注释 + 默写 + 编译验证"
真正掌握数据结构代码的工具。它不是视频课、IDE、题库，是一整个陈越
数据结构课程蒸出来的一个小知识库。

三个形态都能用：桌面便携版（双击就开，不用装）、在线版（打开链接就能看）、
每段动画单独的 SVG 文件（能贴在 README 里自动播放）。

一开始只是想自己用，做到后面觉得别人可能也需要，就做成了能给别人用的样子。

============================================================
三、给谁用
============================================================

和我一样正在学数据结构的大学生：能看懂代码但独立写会卡壳；考前要快速过一遍；
希望有个地方能随时查各类算法八股文。

============================================================
四、功能
============================================================

4.1 模块化阅读

把完整代码切成独立模块。单链表切成 12 块：结构定义、creatNode、InitList、
applist、GetElem_L、LocateElem、ListInsert、ListDelete、printList、freeList、
main、完整源码。每个模块顶部显示：模块名、一句话作用、难度星级、依赖模块、
前置视频。

为什么这样切：300 行一起看会懵，
但是一次只看 15 行的 ListInsert可以帮我聚焦注意力和背诵默写。

4.2 三档注释

详细注释（逐行解释 + ASCII 指针图）、精简注释（只标关键步骤）、
无注释（只有纯代码）。

切到"无注释"时，函数签名、变量名、缩进完全不变，只把注释剥掉。
这条是硬要求：如果连代码本身都变了，就不能拿来练默写了。

例如 ListInsert 详细注释里的图：

插入前：
p            p->next
↓              ↓
[a_{i-1}]  →  [a_i]  → ...

插入后：
p         s        p->next
↓         ↓          ↓
[a_{i-1}] → [新] →  [a_i] → ...

① s->next = p->next;   先连后
② p->next = s;         再连前
顺序反了就丢了 a_i

4.3 空白编辑器 + 编译

点"编辑模式"切换到默写：一开始完全空白，不给你抄；有语法高亮和行号；
写完 Ctrl+Enter 编译，错了标红并点得到错误行；右边可以展开参考答案对照。

编译器优先用系统 gcc，没装就用项目自带的，不用配环境。

为什么重要：默写最怕"以为写对了"，编译一下错在哪一目了然。

4.4 动画

每个模块配动画：链表指针转向、栈的入出、队列进出、AVL 旋转、
DFS/BFS 点亮、排序柱子交换、哈希探测。

到 v2.1.3 做了 188 段，覆盖全部已完成模块，没有遗漏。

我提的要求是：进度条能拖、能变速、能单步、能循环。

为什么进度条一定要能拖：
其实我感觉只能从头播的动画等于没有，我的思考速度要由我决定而不是动画。

动画和代码要联动：动画播到"分配新节点"，右边对应那行代码跟着高亮；
点代码某行，动画跳到对应那一帧。

五、v2.0 扩展
============================================================

v1.0 只有单链表。但是我学完之后还有栈、队列、树、图、排序、哈希。
每换章节重新再vibecoding一个工具太麻烦
所以 v2.0 扩到陈越老师《数据结构》全课程。

三层导航：01 引论 / 02 线性结构（线性表、链表、堆栈、队列）/ 03 树（二叉树、
BST、AVL、堆、哈夫曼、并查集）/ 04 图（遍历、最短路径、最小生成树、拓扑排序）/
05 排序 / 06 散列。每个模块右侧显示状态：未学 / 默写中 / 已通过。

02-02 链表是重点，分三个 Tab：[单链表] [双链表] [对比]。为什么要对比：
双链表不只是一个 prior 指针，插入顺序也变了，放一起才看得清。

到 v2.1.3 的实际进度：规划 25 节、214 个模块，已经做完入库 186 个。

============================================================
七、技术
============================================================

代码都是 AI 写的，我没动手写。下面说的是我为什么选这些东西。

套一层 Electron
  我想一套东西同时有桌面版和网页版，不想写两遍。所以用 Electron 套一层，
  同一个界面既能打包成 exe，也能直接放网页上。

内容和程序分开
  所有模块、三档注释、动画数据都放在 JSON 里，不放程序里。
  这样以后加一节新内容，不用动程序。

数据从代码生成
  一开始不是这样，改一个地方要改好几处，老漏。现在都从 C 代码自动生成
  （下一节细说）。

要能自己检查
  东西一多，改坏了不容易发现。所以配了一套自动检查，跑一遍就知道。

【还没碰过的】
前端框架和后端我都不会。现在界面是手写的 HTML/CSS/JS，页面不多够用；
没有后端，因为是本地程序加静态网页，用不着服务器。
这两块等以后要把检索工具接到网上再说。

【说实话】
上面这些是我看代码看明白的，具体怎么写我不会。

============================================================
八、数据是怎么走的
============================================================

这一节是我最想说的，因为它不是某个功能，是整个东西的骨架。

原来的问题：

v2.0 的时候，网页、动画、文档是分开的。我改一次 C 代码，要分别去改这三处。
改漏过好几次，每次都要来回找，很烦。

现在的做法：

只留一份"C 代码"，其他全都从它生成，一层一层往下走：

  C 代码（唯一要维护的东西）
     ↓
  数据文件（模块、三档注释、动画数据）
     ↓
  动画
     ↓
  在线版网站 + 便携 exe

  旁边还有一条：检查，随时能跑，改坏了立刻知道

好处：我只管一份东西，改完跑一下，后面全部跟着变，不会再漏。

这个办法是它想出来的，我提的是效果：改一处，别的地方得自己跟上。

【我在这上面想的事】
东西一多，最大的麻烦不是写不出来，是"改了这里忘了那里"。
所以我一直在往"少维护几份东西"的方向上想：能自动生成的就不手写，
能放在一起的就别分开。上面这套就是这么来的。
（说是这么说，具体怎么做还是 AI 的事。）

============================================================
九、验收
============================================================

用起来的部分：导航能折叠能搜、链表三个视图能切、三档注释切过去代码结构
不变、每模块都有动画、进度条能拖能变速能单步、代码和动画高亮对得上、
编译正常、桌面端和网页端都能开。

我自己最在意的四条：
· 动画任意时刻都得有内容显示，不能有空窗
· 三档注释必须逐字节一致，不能只"看起来一样"
· 动画循环播放时首尾要接得上，不能跳
· 本地、桌面、下载页三处的文件校验值要一致

这十几项一起跑就是那 10738 条检查，结果必须是 0 个失败。

============================================================
十二、另外两件事
============================================================

一个检索小工具

项目里那 186 个模块本来就是分好块的材料。我一直对 AI 感兴趣，就想到能不能
让它自己去这些模块里找答案。做法两步（代码是 AI 写的）：先搜出最相关的 3 个
模块，再把这 3 个连同问题发给 DeepSeek，让它只根据这些内容回答并注明来源。

检索用的是"倒排索引"，就是数据结构课上学的那个——先建一张
"词 → 哪些模块里有这个词"的表，查的时候直接跳过去。这是这个项目里我唯一
能说清原理的地方。

踩过一个坑：一开始按单个汉字切，查"指针"返回的第一个是"头文件与 typedef"
——因为"指"和"针"在很多模块里都出现过。后来改成按相邻两个字切才有意义。

这个工具现在还不算好用，检索有时候找不到。不过检索和生成是分开的，
哪一半不准能看得出来。
