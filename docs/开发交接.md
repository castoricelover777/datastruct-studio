## 一、这个项目是什么

**DataStruct Studio（数据结构研习社）** —— 一个 Windows 单文件便携工具，用来**学好陈越《数据结构》里的代码**。

核心学习循环（这是产品的灵魂，不要改）：

```
分模块阅读  →  去注释裸看  →  空白默写  →  一键编译验证
```

- 每个模块有三档注释：**详细 / 精简 / 无注释**，三档的**代码部分逐字节相同**（切档只增删注释行）
- 练习模式给一个"脚手架"（依赖模块已给出、目标模块留空、附测试驱动），用户默写完按 `Ctrl+Enter` 编译运行，和官方实现对照
- 每个模块配一段动画，动画和代码**双向联动**（动画走到哪，右边代码高亮到哪）

**仓库**：https://github.com/castoricelover777/datastruct-studio
**在线版**：https://castoricelover777.github.io/datastruct-studio/
**作者 GitHub**：`castoricelover777`

## 三、架构：最关键的设计

### 1. 单一真相来源 —— 可编译的标注 C 文件

**这是整个项目最值钱的设计，务必保持。**

`resources/reference/<节>/modules.c` 里是**能直接编译的 C 代码**，模块边界用注释标记：

```c
//%module | 01 | typedef | 头文件与 typedef | 1 |
//%summary | 一句话说明这个模块干什么。
//@d ============ 详细档才有的扩展说明 ============
//@s 精简档也保留的短说明
typedef struct { ... } SeqList;
//%end
```

所有标记都是**合法的 C 注释**，所以：
- 源文件可以直接 `gcc` 编译（自检会验）
- 构建脚本能从同一份文件抽出三档注释 + 脚手架 + 元信息

`resources/reference/<节>/drivers.c` 里是测试驱动：

```c
//%driver | 01
int main(void) { /* 只调用本模块（target）自己的东西 */ }
//%driver-end
```

**驱动块的编号要和模块编号对应**（`//%driver | 02` 对应模块 02）。

### 2. 构建流水线

```
resources/course.json            课程大纲（章 → 节 + 章色带 + 完成状态）
resources/reference/<节>/*.c     标注源码（可编译）
resources/animations/<节>.js     动画场景定义
        ↓  node tools/build-data.js
data/tree.json                   章节树（启动只读这一个）
data/chapters/<章>.json          选中章时读
data/code/<节>.json              三档代码 + 脚手架 + 预期输出
data/animations/<节>.json        动画关键帧（含 line，供代码联动）
data/coverage.json               覆盖清单
        ↓  node tools/make-animations.js
docs/animations/<场景id>.svg     单段动画（README 里 <img> 直接能播）
docs/animations/index.html       画廊
```

**预期输出必须由真 gcc 跑出来**，不许编造。`build-data.js` 里每个模块都会编译 + 运行 + 抓 stdout。

### 3. 动画：一套数据两种消费方式

动画数据是**内联 SMIL 的 SVG**：

- 放进 README 用 `<img>` 引用 → **自动播放**
- 应用内联进 DOM 后，用 SVG 原生的 `pauseAnimations()` / `setCurrentTime(t)` → **可拖动、可变速**

所以播放器的拖动就是连续 `setCurrentTime`，画面自然实时跟随。

### 4. 三种渲染器（`tools/anim/render.js`）

| variant | 用途 | 关键点 |
| --- | --- | --- |
| 默认（`singly`/`doubly`） | 链表 | 结点 + 箭头通道（`NEXT_Y` / `PRIOR_Y`） |
| `array` | 顺序表 / 栈 / 队列 / 排序 / 散列 | 格子阵列，`CELL_W=58 CELL_H=46 CELL_Y=104` |
| `tree` | 二叉树 / BST / AVL / 堆 / 哈夫曼 | **中序遍历定列、深度定行**，行距按深度自适应（36~62px） |
| `graph` | 图（无向/有向/带权） | 顶点坐标手写，渲染时经 `fitSafeArea()` 压进安全区 |

**画布纵向布局（写场景时务必记住）** —— 画布高 **340**（原来是 300，2026-09 加高，因为七层挤在 300px 里标注没地方放）：

```

104~150  格子行        ~163  格子下方的下标
182   cellArrows 的虚线        ~197  cellArrows 的文字
210   ← 标注文字（notes）唯一能待的地方
250   字幕（每步说明）
276   代码行（有些步骤带 code）
308   进度条
```

树/图的安全区是 `x∈[90,870] y∈[84,198]`（`SAFE` 常量，**没跟着画布加高变**）。

**场景要结点几何时，必须用 `render.js` 导出的常量**（`NODE_Y` / `NODE_H` / `MID_Y`），
不要再自己算一遍 —— 2026-09 就因为这两个场景自己算、而 `render.js` 当时没导出，
`MID` 静默变成 `NaN`，引出线和标注全部画到画面外（详见第五节 A 组最后一条）。

### 5. 语义核验：文案说的和画面做的是不是一回事

`lint-anim.js` 管机械问题（空画面、越界、重叠），**`check-anim-semantics.js` 管语义**：

```bash
node tools/check-anim-semantics.js              # 全部：72 个格子阵列场景 / 642 个步骤
node tools/check-anim-semantics.js 05-01        # 只看一节
node tools/check-anim-semantics.js --detail 05-01-02   # dump 某段完整时间线（调试神器）
```

做法：把每个 step 时间点的**真实可见画面**抽成快照（每格显示什么值、高亮哪几个），
再和**文案声称的动作**对照。五类检查：

| 检查 | 抓的是什么 |
| --- | --- |
| ① 文案的数列在画面里没出现 | 文案说"结果 1 2 3 4 5 8"，本步窗口内没有任何一刻是这串数 |
| ② 说要交换，画面没动 | 文案描述交换，但本步里没有格子改值 |
| ③ 画面变了，文案没提 | 多了/少了格子却没有任何动作词，也没点名那个数 |
| ④ 说不该变，画面变了 | 文案拿"保留/不变"当主干说，画面却在换值 |
| ⑤ 文案点名的数值画面里没有 | 文案和画面在说两件事 |
| ⑥ 位置断言和画面对不上 | 文案写"下标 3 是 5"，那格就必须是 5（全语料命中 4 处，都在 `02-01-05`、`05-04-02`） |

**覆盖范围要说清楚**：自动判定的是 `variant: 'array'` 的 **72 个场景 / 642 个步骤**（全部 188 段
里的格子阵列那部分）。链表、树、图共 116 段**只提供 `--detail` 时间线 dump，不做自动判定** ——
试过"结点出现/消失但文案没点名值"，44 处全是噪音（链表里"造出新结点 s（数据域填 e）"
本来就不必在文案里写数值），这类没有共识基础，宁可不查也不误报。

**误报是这么免掉的**（照着加，别把规则放松）：讲原理/讲做法/否定句（"如果用…就交换"、
"不用两两交换"、"代替"）、讲代码细节（"边界检查"、"哨兵"）、以及**文案已经点名前后的
数值**（"8 被顶到了 A[0]"）都不算不符。

**这个工具最大的价值不是"扫出问题"，而是给写场景立了一条可验证的规矩**：

> 文案里出现一句具体的动作或结果，**格子必须在同一时刻变**；
> 结果句（"结果 1 2 3 4 5 8"）尤其要命 —— 它一到，画面就得是那个数组。

2026-09 全量跑出 40 处可疑，逐条判定后修了 8 处真不符（详见提交 `e9cdc3d`），
其余收窄成免报。**写新场景、改完场景都要跑一遍**。

### 6. 全面彻查：模型 vs 产物（`audit-array-anims.js`）

用户连着截到"一排空框"和"两个指针标签叠在一起"之后加的。它不抽查，按同一套口径
把所有动画过一遍：

```bash
node tools/audit-array-anims.js        # 全部；也可传章节前缀
```

| 检查 | 内容 |
| --- | --- |
| ⓪ 连续空屏 | **所有 188 个场景**沿时间轴取样，画面元素全不可见超过 1.2s 就报（字幕/标注不算画面有东西） |
| ① 逐格核对 | 模型说某时刻第 N 格该显示某值，产物**同一列**上必须真有它且亮着 |
| ② 整排空框 | 和场景自身峰值比：曾经到过 ≥3 格、却有一连 ≥1s 一格值都没有 |
| ③ 同格指针重叠 | 同格指针错开后总宽会不会压到隔壁 |

**判据要分清真伪**，这几条是踩出来的：
- 取样点要**避开换值瞬间**（段的两端），否则模型与产物的交接处会出现一堆假命中
- 空态本身不是问题（栈空、空表就该空），只有"空且持续"才算 —— 否则每个栈场景都会误报
- "开局还没铺开"不算空框，要和场景自身的峰值比

2026-09 全量跑出 8 处真问题（`InitQueue` 标签重叠、`BSTDelete` 前 47% 空屏、
`InitList_Sq` 半排问号半排空框、`QuickSort` 前一半没数组可看、`InfixToPostfix`
少画一个栈元素、freeList/main/FreeTree 的尾部死画面），全部修掉。

## 五、踩过的坑（**重要，别再踩**）

### A. 写代码时

| 坑 | 症状 | 规矩 |
| --- | --- | --- |
| **中文里敲 ASCII 双引号** | C 语法错误 `expected ')'` | 中文强调一律用「」。有 `tools/lint-quotes.js` 守着 |
| **辅助函数写在 main 模块里** | driver 调用它 → `redefinition of 'main'` | **main 模块里只能有 main**；`FreeXxx`/`CheckXxx`/`PrintXxx` 一律独立模块 |
| **driver 调用依赖 target 的模块** | `unknown type name` / 顺序错乱 | **driver 只能调 target 自己的东西**。typdef 类模块的 driver 连 `InitXxx` 都要小心 |
| **`//%summary` 写成 `//@summary`** | summary 为空，自检才报 | 写模块头时核对一遍 |
| **驱动块漏 `//%driver-end`** | 后面的驱动被吞掉 | 每个 driver 都要闭合 |
| **`NextPrime` 上界太小** | `NextPrime(1000)` 返回非素数 1001 | 已修：先从 N 本身检查 + 上界 20000 |
| **`vis: [[0, 99]]` 的 99 是哨兵值，不是秒数** | 拿它当秒数算淡出 → `keyTimes` 写出 `99/12 = 8.25`，**超过规范允许的 [0,1]** → 浏览器把这项动画当坏数据，元素在正片放到 2/3 时**整段消失**（用户截到的 TableSort 空框）。188 段动画全中，310 处越界 | 渲染时要按 `total` 归一/夹紧；`lint-anim-loop.js` 会硬查 keyTimes 是否落在 [0,1] 且单调不减。**任何"用大数表示永久"的约定都要在渲染前夹回范围** |
| **把未初始化内存的值打印进预期输出** | 产物每次重建都变（`data/code/*.json` 自己就变了），桌面版和在线版显示的数字还不一样 | 预期输出由**真 gcc 跑出来**，所以任何读未初始化内存的 `printf` 都会把随机数写进产物。driver 里要打印时只描述"这是未定义的"，别打具体值（`02-02-链表/doubly` 的 driver 踩过） |
| **从 `render.js` 解构它没导出的常量** | 场景里 `MID` 全变 `NaN`，引出线/标注静默画到画面外，**不报错** | `const { NODE_Y } = require(...)` 拿到的是 `undefined`，解构 undefined 不会抛异常。**改 render 的导出前先搜一遍谁在解构它**；写完场景顺手看一眼生成的 SVG 有没有 `NaN` |

### B. 写动画场景时

这些**都已经有工具兜底**（`lint-anim.js` + `normalize.js`），但知道原因能少返工：

| 坑 | 症状 | 现在的兜底 |
| --- | --- | --- |
| **元素从 0.6 秒才开始** | t=0 画面全空 | `alignStart` 把最早出现的时刻归零 |
| **同一格数字时间重叠** | 两个数字叠在一格（"数字显示不正常"） | `chainCells` 强制首尾相接 |
| **同一格中间留空档** | 某一瞬间格子是空的 | 同上，无条件串联 |
| **标注 y 写到 232/258** | 压住字幕/进度条 | `clampNotes` 统一钉到 **210** |
| **同位置标注时间重叠** | 两句话叠在一起 | `unstackNotes` 按时间串联，**每条给后续预留 0.8 秒** |
| **图顶点 y 写到 274** | 压住字幕 | `fitSafeArea` 压进安全区 |
| **场景文件里用 `require` 的缓存** | 改了场景但产物没变 | 记得 `node tools/make-animations.js` 重新生成 |
| **场景 id 改名后旧 SVG 留在产物里** | 孤儿文件一直挂在 Pages 上被当成内容 | `make-animations.js` 全量生成时自动清理 + `verify.js` 有孤儿检查（见 `03-01-08-main` 那次） |
| **排序场景只写"结果"没写"初始数组"** | 打开播放器看到一排空框（用户截图报的） | `lint-anim.js` 的「格子全程应有值」只卡 `bookTag === '排序'` 的场景 |

| **同一格上的多条指针标签会精确重叠** | `InitQueue` 的 `front` / `rear` 都写在 `at: 0`，两个字叠成一团看不清 | 渲染器现在会自动左右错开 + 补引出线；`lint-anim.js` 再兜一道（错开后不能压到隔壁格） |
| **结点/格子的可见区间只在后半段** | 画面长时间空白 —— `BSTDelete` 的树写在 `[[5.6, 12]]`，前 47% 是空屏，而那段正要指着树讲"删叶子" | 讲哪一段就把**那一段要用的东西**摆出来。跑 `audit-array-anims.js` 的"⓪ 连续空屏"（它会扫所有 188 段） |

## 九、协作风格上的注意事项

上一个会话里我犯过一个毛病：**思考时反复输出"好。"形成回声循环**，工具调用被淹没，用户连续几次说"卡了"。

这个会话（2026-09 接手）又犯了三个新毛病，都记下来：

1. **`git add -A` + 提交信息文件写进仓库**：把 `.git-msg-*.txt` 自己也提交了，连着踩两次。
   规矩：提交信息文件放**仓库外**（或 commit 后确认 `git status` 干净），别用 `git add -A` 扫全盘。
2. **`git add` 里塞了不存在的路径 → 整条命令中止**，我误以为"改动已暂存"就提交了，
   结果提交里只有两个删除。规矩：`git add` 后**一定 `git status` 看一眼暂存区**再 commit。
3. **`node -e "..."` 内联长脚本**被 PowerShell 吃引号，浪费了三轮。
   规矩见第六节末尾：临时脚本一律写成文件。

- 思考要短，直接执行命令、看结果、再执行
- 不要为每一步都写一段分析
- 会话过长时会退化 —— **该开新会话就开**

用户的工作方式：
- 会说"继续"，意思是**按既定节奏往下做、做完报告**
- 要求**一节一节来**，每节做完报告进度（他选的节奏）
- 重视**实证**：不要编造编译输出，不要声称验证过没验证的东西
- 发现问题要**如实说**，包括自己写错的（他明确要求过"如实说"）
