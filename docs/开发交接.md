## 一、这个项目是什么

**DataStruct Studio（数据结构研习社）** —— 一个 Windows 单文件便携工具，用来**学好陈越《数据结构》里的代码**。

核心学习循环（这是产品的灵魂，不要改）：

```
分模块阅读  →  去注释裸看  →  空白默写  →  一键编译验证
```

- 每个模块有三档注释：**详细 / 精简 / 无注释**，三档的**代码部分逐字节相同**（切档只增删注释行）
- 练习模式给一个"脚手架"（依赖模块已给出、目标模块留空、附测试驱动），用户默写完按 `Ctrl+Enter` 编译运行，和官方实现对照
- 每个模块配一段动画，动画和代码**双向联动**（动画走到哪，右边代码高亮到哪）

**仓库**：https://github.com/castoricelover777/datastruct-studio
**在线版**：https://castoricelover777.github.io/datastruct-studio/
**作者 GitHub**：`castoricelover777`

## 三、架构：最关键的设计

### 1. 单一真相来源 —— 可编译的标注 C 文件

**这是整个项目最值钱的设计，务必保持。**

`resources/reference/<节>/modules.c` 里是**能直接编译的 C 代码**，模块边界用注释标记：

```c
//%module | 01 | typedef | 头文件与 typedef | 1 |
//%summary | 一句话说明这个模块干什么。
//@d ============ 详细档才有的扩展说明 ============
//@s 精简档也保留的短说明
typedef struct { ... } SeqList;
//%end
```

所有标记都是**合法的 C 注释**，所以：
- 源文件可以直接 `gcc` 编译（自检会验）
- 构建脚本能从同一份文件抽出三档注释 + 脚手架 + 元信息

`resources/reference/<节>/drivers.c` 里是测试驱动：

```c
//%driver | 01
int main(void) { /* 只调用本模块（target）自己的东西 */ }
//%driver-end
```

**驱动块的编号要和模块编号对应**（`//%driver | 02` 对应模块 02）。

### 2. 构建流水线

```
resources/course.json            课程大纲（章 → 节 + 章色带 + 完成状态）
resources/reference/<节>/*.c     标注源码（可编译）
resources/animations/<节>.js     动画场景定义
        ↓  node tools/build-data.js
data/tree.json                   章节树（启动只读这一个）
data/chapters/<章>.json          选中章时读
data/code/<节>.json              三档代码 + 脚手架 + 预期输出
data/animations/<节>.json        动画关键帧（含 line，供代码联动）
data/coverage.json               覆盖清单
        ↓  node tools/make-animations.js
docs/animations/<场景id>.svg     单段动画（README 里 <img> 直接能播）
docs/animations/index.html       画廊
```

**预期输出必须由真 gcc 跑出来**，不许编造。`build-data.js` 里每个模块都会编译 + 运行 + 抓 stdout。

### 3. 动画：一套数据两种消费方式

动画数据是**内联 SMIL 的 SVG**：

- 放进 README 用 `<img>` 引用 → **自动播放**
- 应用内联进 DOM 后，用 SVG 原生的 `pauseAnimations()` / `setCurrentTime(t)` → **可拖动、可变速**

所以播放器的拖动就是连续 `setCurrentTime`，画面自然实时跟随。

### 4. 三种渲染器（`tools/anim/render.js`）

| variant | 用途 | 关键点 |
| --- | --- | --- |
| 默认（`singly`/`doubly`） | 链表 | 结点 + 箭头通道（`NEXT_Y` / `PRIOR_Y`） |
| `array` | 顺序表 / 栈 / 队列 / 排序 / 散列 | 格子阵列，`CELL_W=58 CELL_H=46 CELL_Y=104` |
| `tree` | 二叉树 / BST / AVL / 堆 / 哈夫曼 | **中序遍历定列、深度定行**，行距按深度自适应（36~62px） |
| `graph` | 图（无向/有向/带权） | 顶点坐标手写，渲染时经 `fitSafeArea()` 压进安全区 |

**画布纵向布局（写场景时务必记住）**：

```
 40   标题          63   副标题
104~150  格子行        ~165  格子下方的下标
186   ← 标注文字唯一能待的地方
214   字幕（每步说明）
240   代码行（有些步骤带 code）
268   进度条
```

树/图的安全区是 `x∈[90,870] y∈[84,198]`（`SAFE` 常量）。

## 五、踩过的坑（**重要，别再踩**）

### A. 写代码时

| 坑 | 症状 | 规矩 |
| --- | --- | --- |
| **中文里敲 ASCII 双引号** | C 语法错误 `expected ')'` | 中文强调一律用「」。有 `tools/lint-quotes.js` 守着 |
| **辅助函数写在 main 模块里** | driver 调用它 → `redefinition of 'main'` | **main 模块里只能有 main**；`FreeXxx`/`CheckXxx`/`PrintXxx` 一律独立模块 |
| **driver 调用依赖 target 的模块** | `unknown type name` / 顺序错乱 | **driver 只能调 target 自己的东西**。typdef 类模块的 driver 连 `InitXxx` 都要小心 |
| **`//%summary` 写成 `//@summary`** | summary 为空，自检才报 | 写模块头时核对一遍 |
| **驱动块漏 `//%driver-end`** | 后面的驱动被吞掉 | 每个 driver 都要闭合 |
| **`NextPrime` 上界太小** | `NextPrime(1000)` 返回非素数 1001 | 已修：先从 N 本身检查 + 上界 20000 |

### B. 写动画场景时

这些**都已经有工具兜底**（`lint-anim.js` + `normalize.js`），但知道原因能少返工：

| 坑 | 症状 | 现在的兜底 |
| --- | --- | --- |
| **元素从 0.6 秒才开始** | t=0 画面全空 | `alignStart` 把最早出现的时刻归零 |
| **同一格数字时间重叠** | 两个数字叠在一格（"数字显示不正常"） | `chainCells` 强制首尾相接 |
| **同一格中间留空档** | 某一瞬间格子是空的 | 同上，无条件串联 |
| **标注 y 写到 232/258** | 压住字幕/进度条 | `clampNotes` 统一钉到 186 |
| **同位置标注时间重叠** | 两句话叠在一起 | `unstackNotes` 按时间串联，**每条给后续预留 0.8 秒** |
| **图顶点 y 写到 274** | 压住字幕 | `fitSafeArea` 压进安全区 |
| **场景文件里用 `require` 的缓存** | 改了场景但产物没变 | 记得 `node tools/make-animations.js` 重新生成 |

### C. 打包与发布

| 坑 | 解法 |
| --- | --- |
| electron-builder 超时 | `$env:ELECTRON_BUILDER_BINARIES_MIRROR='https://registry.npmmirror.com/-/binary/electron-builder-binaries/'` |
| `Lock file is already being held` | 先 `Remove-Item -Recurse -Force dist` |
| **`github.com` 被墙**（API 通） | 走代理：`git config http.proxy http://127.0.0.1:7890`；curl 加 `-x http://127.0.0.1:7890`。**不要再加 `--noproxy '*'`**（那会强制直连） |
| **Pages 不更新** | ① 确认 `git push` 成功（曾三次只 commit 没 push）② `api.github.com/repos/.../pages/builds` 查构建 |
| 桌面 exe 被占用 | `CloseMainWindow()` 温和关闭（不是强杀），等几秒再 `Copy-Item -Force` |
| **PowerShell 处理中文文件** | 永远不要用 `Get-Content -Raw` / `Set-Content`。用 node 脚本或 write 工具。多行 commit message 用 `git commit -F <file>` |

## 七、写一节新内容的完整流程

以"补 07 章"为例：

1. **标记完成**（先做，这样构建会带上它）
   ```bash
   node tools/mark-done.js 07-01 "一句话简介"
   ```

2. **写标注源码** `resources/reference/07-01-XXX/modules.c`
   - 每个模块 `//%module | NN | key | 标题 | 难度 | 依赖 |` + `//%summary` + `//@d`/`//@s` + `//%end`
   - **main 模块里只有 main**，辅助函数独立成模块
   - 中文强调用「」

3. **写驱动** `resources/reference/07-01-XXX/drivers.c`
   - 每个模块一个 `//%driver | NN` … `//%driver-end`
   - **driver 只调 target 自己的东西**

4. **诊断**
   ```bash
   node tools/lint-quotes.js 07-01     # 先扫引号
   node tools/diag-section.js 07-01    # 逐模块真编译真运行
   ```
   修到全绿。

5. **写动画场景** `resources/animations/07-01.js`
   - 导出场景数组，每个场景有 `id/no/title/sub/total/variant/...`
   - 排序/散列用 `variant:'array'` + `cells/notes/steps`
   - 树用 `variant:'tree'` + `tree` + `nodes/edges`（按路径 `root.l.r` 定位）
   - 图用 `variant:'graph'` + `gnodes/gedges`
   - **不必纠结 y 坐标和重叠** —— `normalize.js` 会兜底

6. **构建 + 核验**
   ```bash
   node tools/build-data.js
   node tools/make-animations.js
   node tools/lint-anim.js 07
   node tools/verify.js
   ```

7. **提交推送**
   ```bash
   git add -A && git commit -m "内容：07-01 XXX（N 模块 N 动画）"
   git push origin main      # 走代理！
   ```

8. **重新打包 + 发布**（只在整章做完时做）

## 九、协作风格上的注意事项

上一个会话里我犯过一个毛病：**思考时反复输出"好。"形成回声循环**，工具调用被淹没，用户连续几次说"卡了"。

- 思考要短，直接执行命令、看结果、再执行
- 不要为每一步都写一段分析
- 会话过长时会退化 —— **该开新会话就开**

用户的工作方式：
- 会说"继续"，意思是**按既定节奏往下做、做完报告**
- 要求**一节一节来**，每节做完报告进度（他选的节奏）
- 重视**实证**：不要编造编译输出，不要声称验证过没验证的东西
- 发现问题要**如实说**，包括自己写错的（他明确要求过"如实说"）
