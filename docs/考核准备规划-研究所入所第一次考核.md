## 三、可选加分项：DeepSeek `rag.js`（**已经写好了，这 1 小时省了**）

**这是 1.3 节那条桥的实物。而且不需要你现写——已经写好了，在 `tools/rag.js`。**

### 3.1 它是什么

一个 **RAG（检索增强生成）** 演示，约 250 行，**零第三方依赖**：

| 环节 | 做法 | 说明 |
| --- | --- | --- |
| **R（检索）** | 把 `data/` 里已完成的 **186 个模块**读成 chunk，建倒排索引，按相关度取前 3 | 自己写的——**这是"数据结构"真正派上用场的地方** |
| **G（生成）** | 把命中的 3 个模块拼进 prompt，调 DeepSeek，要求标注来源模块编号 | 一次 HTTP 请求 |

**关键点：知识库不需要你从零建。** 你项目里 186 个模块的标题、简介、代码、动画说明已经在了——**别人要花一周建的语料，你顺手就攒下来了**。

### 3.2 怎么演示（现场 30 秒）

```
$ node tools/rag.js "二叉树的四种遍历"

知识库：E:\deepseek\linklist-studio
已就绪：186 个模块 chunk，21533 个索引词条

[检索] 命中 3 个模块：
   · 03-01-09  main —— 四种遍历摆在一起   （相关度 45，难度 2）
     03 树 / 03-01 二叉树基础
   · 04-02-06  main —— 两种遍历对着看     （相关度 35，难度 2）
     04 图 / 04-02 图的遍历 DFS/BFS
   · 03-01-07  LevelOrder —— 层序遍历      （相关度 23.5，难度 2）
     03 树 / 03-01 二叉树基础

[生成] 调用 DeepSeek…
（回答，末尾标注来源：03-01-09 / 04-02-06 / 03-01-07）
```

**没设 API key 也能跑**——会自动降级成"只检索、不生成"。上面那三条命中就是 RAG 的 R。

> 桌面包里放了 `rag.js` 和 `rag-提问.cmd`，**双击就能提问**。

### 3.3 你能讲的三个技术点（**唯一需要你额外准备的**）

**① 为什么用倒排索引？**

> "我要在 186 个模块里找最相关的。最笨的办法是每个模块都翻一遍比一遍。**倒排索引是把"词 → 哪些模块有这个词"先建好，查的时候直接跳到候选。**这是我学数据结构学到的第一个"真的用得上"的东西。"

**② 中文为什么要切成两个字？**（问到这题就是加分）

> "我一开始按单字切，结果查"指针"的时候，返回的第一个是"头文件与 typedef"——**因为"指"和"针"这两个字在很多模块里都出现过，单个字区分不出来。**后来我改成切**相邻两个字**，"指针""遍历""队列"这样才有意义。"

**③ 检索和生成分开有什么好处？**

> "分开之后，**检索那半边能单独验证**。我不调 API 就能看出它召回得准不准——那三条命中就是这么测出来的。如果混在一起，出了问题我不知道是搜错了还是模型答错了。"

### 3.4 三个必须注意的点（**面试可能正好问这些**）

1. **API key 绝不写进代码**。用环境变量 `$env:DEEPSEEK_API_KEY="sk-..."`。
   可以主动说："**我把 key 放在环境变量里，不进仓库——这是我做项目时养成的习惯。**"
2. **一定要有降级**：没网 / 没 key 时只跑检索、打印命中模块，**不崩**（已经做好了）。
3. **★ 别声称它是 Agent。** 它是 **RAG**，是一条固定管线。**主动划清界限**：
   > "它是一次检索 + 一次生成，是**固定管线**。Agent 需要能在循环里自主决定调什么工具、并根据结果调整路径。**Agent 我还没动手做过，我不想把它说成 Agent 来夸大。**"

   —— **主动承认边界，比吹成 Agent 加分得多**，对大一新生尤其是。

#### B 类：技术细节（**必须真会**）

7. **⭐ 188 段动画是怎么生成的？**
   → "**是算出来的**：数据里写了每一帧每个格子在什么位置、显示什么，然后根据这个算坐标，生成 SVG 的动画标签。**不用 JS，所以能直接放进 GitHub 的 README 里自动播放。**"

8. **SMIL 是什么？为什么不用 JS 动画？**
   → "SVG 自带的一种动画写法。**选它是因为我的检查程序能精确跳到任意时刻去截图对比**——用 JS 动画就做不到了。"（⚠️ **别说"我需要 setCurrentTime"，说不出原理反而扣分；说"我的检查需要跳到某一刻"就够了**）

9. **10738 条检查检查什么？**
   → "几类：数据文件完不完整、三档注释的代码是不是一模一样、动画关键帧接不接得上、颜色字号统不统一、发版文件的哈希对不对。"

    → **背 2.6 节那段 `keyTimes` 的故事**。**练到能一口气讲完。这是你最能打的一张牌。**

    → 如实说，见 2.6 节话术。**不要含糊其辞，也不要往多了说。**

#### C 类：视野与深度（**这一栏要诚实，别装懂**）

14. **⭐ Agent 和普通程序的区别是什么？**
    → "我的理解比较粗：普通程序是**输入什么就得到什么，路线是定死的**；Agent 是**自己在一个循环里决定下一步做什么**——先看情况、再挑工具、看结果、再调整。**所以它的输出不确定，需要额外做检查和兜底。**（**我只是从资料上理解的，没动手做过。**）"

15. **Agent 的核心组件？**
    → "资料上说有感知、规划、记忆、工具调用这几个部分。**我自己只真正碰过"记忆"那一点——我项目里那些 JSON 文件就相当于把做过的事存下来，下次还能读。**"

16. **⭐ RAG 是什么？你会怎么用？**
    → "检索增强生成。**大模型不知道我项目里的内容，所以先去我的知识库里搜相关片段，再让模型只根据这些片段回答。**我把 186 个模块当成语料，写了个检索，后面接 DeepSeek 生成。**检索那半边是我自己写的，能单独测。**"

17. **你那个 `rag.js` 是 Agent 吗？**（主动划界，加分）
    → "**不是。**它是 RAG，是**固定管线**：一次检索、一次生成。Agent 需要自己决定调什么工具、根据结果换路线。**Agent 我还没动手做过，我不想把它说成 Agent 来夸大。**"

18. **了解哪些 Agent 框架？**

19. **大模型的幻觉问题你怎么看？**

#### D 类：反思与规划
